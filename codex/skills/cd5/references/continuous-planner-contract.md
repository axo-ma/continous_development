# CD5 Continuator and Controls — контракт архитектуры

Актуальное прямое уточнение пользователя1Nov2026. Оно заменяет прежнее правило,
по которому штаб удалял файл включения при вопросе или завершении.

## Два независимых состояния

- `continue_HQ` — пользователь включил Continuator для этого штаба. Только явная
  команда пользователя включает или выключает его. Штаб самостоятельно файл
  не создаёт, не удаляет, не обновляет и не восстанавливает после завершения.
- `suspend_HQ` — выполнение штаба приостановлено. Штаб создаёт его перед
  завершением всего плана или действительным обязательным ожиданием по проверенному
  требованию пользователя/системы, если другой полезной работы нет.
  Промежуточный отчёт и завершение одной подзадачи не требуют приостановки,
  если остаётся полезная разрешённая работа.

## Команды и события

| Команда или событие | Действие |
| --- | --- |
| Включить континуатор / Enable Continuator | Создать только continue_HQ |
| Отключить континуатор / Disable Continuator | Удалить только continue_HQ |
| Продолжай; продолжить/запустить HQ, штаб, планер; Start Planner | Удалить только suspend_HQ |
| Остановить HQ, штаб, планер; Stop Planner | Создать только suspend_HQ |
| Кнопка ■ | Прервать текущий ход штатно и создать suspend_HQ |
| Проверенное обязательное требование блокирует весь план или весь план завершён | Штаб создаёт suspend_HQ с причиной в CHECKPOINT |
| Квота300мин>=90% или квота неизвестна | Оба файла не менять; новые продолжения запрещены |
| После сброса квота<90% | Можно продолжать, если continue_HQ есть и suspend_HQ нет |

HQ, штаб, Planner и планер в этих командах означают один управляемый чат.
«Продолжай» само по себе не включает Continuator. Включение Continuator само
по себе не снимает приостановку HQ. Текстовая остановка запрещает следующие
запуски; кнопка ■ нужна для немедленного прерывания текущего хода.

## Одна служба и условие отправки

Одна скрытая служба под управлением задачи Windows с восстановлением обслуживает несколько явно
подключённых штабов. У каждого пять файлов памяти, controls и актуальный
Planner Chat из CHECKPOINT.owner.thread_id. Continuator отправляет ровно
**«Продолжай»**. Постоянные правила находятся здесь и в lifecycle.md, а не
повторяются длинным сообщением. Встроенные Goal агентов не являются драйвером CD5.

Для отправки одновременно нужны: явное подключение, continue_HQ,
отсутствие suspend_HQ, свободный чат, свежая обычная квота300мин<90%, разрешённая
точная модель и определённый результат предыдущей отправки. Неопределённую
отправку не повторять. Во время квотной паузы служба ждёт без модели;
штаб сохраняет checkpoint и заканчивает ход, не создавая suspend_HQ из-за квоты.

Continuation не разрешает новые научные действия и не меняет протоколы/бюджеты.
Установка, миграция и передача владельца не включают отключённый Continuator.
Реальный вход Windows и перезапуск Codex считать проверенными только после
отдельной фактической проверки.

## Совместимость

При переименовании существующий continue_planner переносится в continue_HQ
как уже сделанный выбор пользователя; отсутствующий файл не восстанавливается.
Существующие stop_planner и Stop Goal переносятся в suspend_HQ без незащищённого
промежутка. Поздние старые Interrupt остаются запретом до явного запуска штаба.
Исторический Continue Goal не включает Continuator. Прежний Continue Planner
может служить только алиасом запуска штаба, а не включения Continuator.

Решения по протоколу, внутреннему бюджету, ремонту и приёмке входят в полномочия
HQ; это не причины задавать новый вопрос и создавать suspend_HQ. См.
[полномочия штаба](hq-authority.md). Конец CU/попытки не равен концу всего плана.

Управление процессом, heartbeat, журнал и проверка восстановления описаны в
[восстановлении Continuator](continuator-recovery.md). Старый connected в STATUS
не считается доказательством живого процесса.
