# CD5 Goal и одна общая служба продолжения

Собственная цель CD5 — согласованные задачи и вехи в пяти канонических файлах
штаба. Встроенная Goal агента не является её драйвером. Не создавать и не
возобновлять native Goal для CD5; два механизма не конкурируют. Чужие активные
штабы и их Goal не менять, историю и расход сохранять.

## Что хранится где

Одна служба на учётную запись Windows обслуживает несколько явно подключённых
штабов по очереди. REGISTRY.json содержит только разрешённые корни проектов и
настройки связи, а не отдельные цели. У каждого HQ остаются OUTLINE, CHECKPOINT,
KNOWLEDGE, EVIDENCE, ATTENTION. Текущий Planner Chat берётся из
CHECKPOINT.owner.thread_id при каждом обходе и перед отправкой. После принятой
передачи владельца старый чат не получает продолжения; его команды больше не
меняют флаги этого HQ. Служба не выполняет саму передачу.

Два управляющих файла лежат в <canonical-memory>/goal-control:

| Файлы | Действие |
| --- | --- |
| Есть Stop Goal, включая случай обоих файлов | Нет отправки |
| Ни одного | Нет отправки |
| Только Continue Goal | Проверить свободный чат и квоту, отправить одно продолжение, ждать результата |

Точная пользовательская команда Stop Goal создаёт Stop Goal. Continue Goal
создаёт Continue Goal и удаляет Stop Goal. Регистр и пробелы по краям не важны.
Штатный UserPromptSubmit обрабатывает эти команды без модели. Цитаты и
автоматические сообщения не снимают Stop. Stop запрещает следующие запуски;
текущий ход может закончиться. Для немедленного прерывания пользователь
нажимает ■: Interrupt дополнительно создаёт Stop Goal.

Сервис только читает флаги, реальную занятость и свежую квоту300мин<90, затем
посылает продолжение. Он не решает, выполнена ли задача и почему чат простаивает.
Штаб удаляет Continue перед ожидаемым завершением, обязательным вопросом
человеку или квотной остановкой. Промежуточный отчёт не означает завершения.
Только явный пользовательский Continue снимает Stop; сервис файлы не меняет.
Полный учёт и остановка вложенных агентов не входят в эту архитектуру.

## Подключение и вход в Windows

По явному разрешению пользователя setup_shared_continuator.py подключает корень
проекта, сохраняет резервную копию hooks.json и готовит одну общую группу
SessionStart / UserPromptSubmit / Interrupt. Группа читает актуальных владельцев
из канонической памяти. Посторонние определения не меняются. Точная копия
обработчика и зависимостей сохраняется с хешем; доверие к точному определению
остаётся действием человека в настройках Hooks. Установка не создаёт Continue,
не удаляет Stop и не запускает задачи.

Одна запись HKCU Run «CD5 Continuator» запускает скрытый pythonw-процесс при
входе пользователя. Общая блокировка не допускает второго экземпляра при
повторном запуске. При миграции завершить только проверенный старый процесс
однопроектной версии; флаги и незавершённые отправки не сбрасывать.

Процесс не зависит от унаследованного окружения текущего хода. Штатное событие
подключённого HQ передаёт CONNECTION.json с реальными переменными окружения,
полученными от Codex, и существующим bundled app-tools server.mjs. Служба не
угадывает pipe, не подделывает credentials и не запускает второй app-server.
При обновлении descriptor закрывает прежний клиент и переподключается.
Проверка связи включает настоящий host-вызов квоты, а не только локальный tools/list.

Если приложение закрыто или ещё не предоставило подключение через событие HQ,
служба ждёт без модели. Само открытие приложения без события регистрации не
считать доказанным подключением. Реальный вход в Windows и перезапуск приложения
не объявлять проверенными по наличию записи автозапуска или CONFIG.

Пример подготовки установленным Python:

```
setup_shared_continuator.py --home <user-service-home> --root <authorized-project> --hooks-file <user-hooks.json> --app-tools-cache <actual-app-tools-cache> --mac-script <installed-mac-script> --model <checked-model> --authorized --install-logon
```

Запуск: shared_continuator.py --home <user-service-home>. Для проверки есть
конечный --seconds1–600. Персональные REGISTRY/CONNECTION, флаги и журналы
не коммитить. PID проверять вне песочницы: её список процессов может не показывать
внешний процесс. Служба сохраняет общий STATUS и отдельный SERVICE.json каждого
HQ; это отчёты, а не третьи управляющие файлы. Неопределённую отправку не повторяет,
в том числе после смены владельца. Перед каждой отправкой проверяет точный ID
модели через установленный MAC. Закрытая или неизвестная квота запрещает отправку;
автоматическое восстановление квотной паузы сюда не добавляется.

## История проверок

30Oct2026 прежний однопроектный стенд подтвердил два внешних продолжения,
ручной Interrupt, приоритет Stop при обоих файлах и сохранение запрета после
перезапуска сервиса. Это история узкой проверки, не доказательство новой
многопроектной службы или реального входа в Windows. Результаты новой проверки
записываются отдельно, с явным разделением живых и модельных стендов.
