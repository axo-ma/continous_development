# Продолжение CD5 с двумя управляющими файлами

Это отдельный, явно выбранный пользователем способ продолжения. Установка
навыка сама его не включает. Не запускать его одновременно с native Goal.
Если пользователь выбрал эту схему, она заменяет native Goal для данного штаба;
остальные проекты сохраняют свой выбранный способ работы.

## Архитектура и команды

Один внешний процесс без модели читает два файла в настроенной папке:

| Состояние | Что делает сервис |
| --- | --- |
| Есть Stop Goal, в том числе вместе с Continue Goal | Не отправляет продолжение |
| Нет обоих файлов | Не отправляет продолжение |
| Есть только Continue Goal | Проверяет настоящий статус чата и квоту, отправляет одно продолжение, ждёт результата |

Точная пользовательская команда `Stop Goal` создаёт Stop Goal. Точная команда
`Continue Goal` создаёт Continue Goal и удаляет Stop Goal. Регистр и пробелы
по краям не важны. Эти команды обрабатывает UserPromptSubmit без вызова модели.
Не выполнять управление из автоматических сообщений или цитат команд.

Stop Goal запрещает следующие запуски; текущему ходу разрешено закончиться.
Для немедленного прерывания пользователь нажимает штатную кнопку ■. Событие
Interrupt дополнительно создаёт Stop Goal. Только явная пользовательская команда
Continue Goal снимает этот запрет. Сам сервис никогда не меняет управляющие файлы.
Команда, поступившая во время работы, действует с момента обработки приложением;
немедленное прерывание текстом не обещается.

Штаб удаляет Continue Goal перед окончательным завершением задачи, обязательным
вопросом человеку или остановкой по квоте. Он может пользоваться
`goal_files.finish_or_wait(directory)` либо удалить ровно этот файл обычной
операцией. Stop Goal сохраняется. Не удалять Continue из-за промежуточного отчёта:
пока есть полезные разрешённые шаги, работа продолжается.

## Последовательность и ограничения

`file_continuation_service.py` использует настоящий унаследованный Desktop MCP
канал через bundled app-tools, без второго app-server. Перед каждой отправкой
проверяет idle чата, квоту300мин<90 и точную модель через установленный MAC.
Неизвестная активность/квота запрещают отправку. Исход неопределённой отправки
не повторяется. Счётчик и ожидание результата сохраняются в SERVICE.json;
это отчёт сервиса, а не третий управляющий файл. Блокировка процесса привязана
к папке управляющих файлов и не позволяет двум экземплярам отправлять параллельно.

Режим по умолчанию — ограниченный опыт: limit2–3, seconds1–600. Рабочий режим
`mode=session`, `session_authorized=true`, `limit=null`, `seconds=null` требует
явного поручения на работу этой схемы. Сервис живёт, пока работает его процесс.
Stop Goal оставляет процесс в ожидании следующего явного Continue Goal.
После закрытой квоты прежний Continue не вызывает автоматического восстановления;
нужно новое явное Continue. Возобновление после перезапуска Desktop/компьютера
и автозапуск в системе не входят в эту версию. Не устанавливать планировщик.

## Установка для конкретного штаба

Сначала подтвердить отсутствие конкурирующей native Goal владельца штатным
get_goal; существующую не менять без пользовательского разрешения. Проверить
модель MAC и получить свежую квоту. Затем выполнить установленным Python:

```
prepare_file_continuation.py --root <project> --thread <actual-owner-thread> --server <actual-bundled-app-tools-server> --hooks-file <user-hooks.json> --mac-script <installed-mac-script> --model <checked-model-id> --session-authorized
```

Команда создаёт CONFIG.json, точную копию двух файлов обработчика с хешем,
сохраняет резервную копию hooks.json и добавляет только два обработчика своего
чата. Другие определения остаются. Она не запускает процесс, не создаёт
Continue Goal, не удаляет Stop Goal и не меняет доверие приложения.
Review/trust точного определения остаётся действием человека в настройках Hooks.
Повторная подготовка того же определения не добавляет дубликатов.

После подготовки можно запустить `file_continuation_service.py --config <CONFIG.json>`
в скрытом внешнем процессе с настоящим унаследованным Desktop окружением.
Записать PID и проверить процесс вне песочницы: список процессов в песочнице
может не показывать внешний процесс. Не создавать/подделывать pipe или credentials.
Проверка готовности: виден живой PID, SERVICE.json обновляется, без Continue
счётчик отправок не растёт. Пользователь доверяет двум точным строкам и отправляет
Continue Goal. Для завершения обслуживания сохранить Stop и штатно завершить
только свой проверенный PID. Не обещать, что это остановит другие чаты.
