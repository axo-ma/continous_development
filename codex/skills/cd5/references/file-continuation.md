# Управление Continuator и HQ

Обязательный источник правил — [контракт архитектуры](continuous-planner-contract.md).
Пользователь отдельно включает Continuator через continue_HQ и запускает штаб
снятием suspend_HQ. Штаб управляет только suspend_HQ, сохраняя выбор пользователя.

Общие hooks SessionStart / UserPromptSubmit / Interrupt получают действительное
подключение Codex и обслуживают только текущих владельцев явно подключённых HQ.
Новые определения hooks требуют штатного подтверждения пользователя; доверие
не переносится вручную. Их имя: «CD5 controls: Continuator on/off; HQ start/suspend».
Только точные самостоятельные команды меняют controls; цитата, вопрос о команде
или фраза внутри задания не считается командой. Запуск проходит обычным ходом
чата, даже если Continuator выключен. Включение/выключение и текстовая остановка
могут завершаться обработчиком без модельного хода.

Перед каждым содержательным продолжением владелец читает текущие OUTLINE,
CHECKPOINT, действующий профиль, проверяет suspend_HQ и свежую квоту.
Сохраняет действующие разрешения, бюджеты и ограничения. Не создаёт native Goal.
При завершении всего плана или проверенном обязательном требовании пользователя/системы, блокирующем всю оставшуюся работу, создаёт suspend_HQ, записывает
причину в CHECKPOINT. При>=90% не меняет оба файла и заканчивает текущий ход.
Служба ожидает без модели и продолжает при<90%, если пользователь не остановил HQ.
При отсутствии continue_HQ запуск через пользовательское «Продолжай» не создаёт
его. Автоматическое сообщение не разрешает снимать suspend_HQ: служба отправляет
его только при отсутствующей приостановке; при обнаружении suspend_HQ штаб не работает.

Регистрация выполняется setup_shared_continuator.py. Не подключать чужие HQ
и не запускать второй app-server. Одна скрытая запись входа Windows запускает
службу. Без настоящего подключения Codex она ждёт без модели. Сохранённая
неопределённая отправка требует проверки, а не повторного автоматического запуска.

Внутреннее принятие протокола, уточнение прогноза и исправление попытки выполняет
сам HQ по [правилам полномочий](hq-authority.md), без нового согласования человеком.
