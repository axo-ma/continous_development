# CD5 Continuator and Controls

CD5 controls — блок управления продолжением. Команды пользователя:
**Continue Planner** и **Stop Planner**. Файлы: `continue_planner` и `stop_planner`.
Current Planner Chat — текущий чат планировщика из CHECKPOINT.owner.thread_id.
Встроенные Goal coding agents не используются как драйвер CD5. Согласованные
задачи и вехи остаются в пяти канонических файлах контекста; чужую историю не менять.

## Одна служба и отдельные controls

Одна скрытая служба на учётную запись Windows обходит только явно подключённые
HQ по очереди. У каждого собственные OUTLINE, CHECKPOINT, KNOWLEDGE, EVIDENCE,
ATTENTION и два управляющих файла в <canonical-memory>/goal-control. Имя
существующей служебной папки сохранено для совместимости; имена самих файлов новые.
REGISTRY.json хранит только разрешённые корни и настройки, не параллельную систему целей.

| Файлы | Действие службы |
| --- | --- |
| Есть stop_planner, в том числе вместе с continue_planner | Не продолжает |
| Ни одного | Ничего не делает |
| Только continue_planner | Проверяет свободный чат и свежую квоту<90%, отправляет одно продолжение, ждёт результата |

Continue Planner создаёт continue_planner и снимает stop_planner. Stop Planner
создаёт stop_planner. Регистр и пробелы по краям не важны. UserPromptSubmit
обрабатывает точные команды без модели; цитаты и автоматические сообщения не
снимают Stop. Кнопка ■ немедленно прерывает текущий ход, Interrupt дополнительно
создаёт stop_planner. Текстовая команда только запрещает следующие запуски.

Штаб удаляет continue_planner перед ожидаемым завершением, обязательным вопросом
или квотной остановкой. Промежуточный отчёт не означает завершения. Continuator
реализует исключительно продолжение неожиданно остановившегося разрешённого
чата: он не анализирует задачи и причины простоя, не управляет controls.
Полный учёт вложенных агентов не входит в задачу.

## Безопасный переход имён

Установщик/HQ вызывает planner_controls.migrate при остановленной службе.
Старый Stop Goal сначала превращается в stop_planner; только после создания
нового запрета старый файл удаляется. Старый Continue Goal архивируется и
**не создаёт** continue_planner: миграция не включает работу. Для включения
нужен новый явный Continue Planner. Новые controls при повторной миграции сохраняются.

На время перехода читатель признаёт старый файл Stop Goal как запрет, если его
успеет создать прежний доверенный Interrupt. Старый Continue никогда не разрешает
работу. Команда Stop Goal остаётся только защитным совместимым выключением;
Continue Goal блокируется с подсказкой использовать Continue Planner и не снимает
запрет. Это временная совместимость, а не канонические команды. Старые пути
импорта goal_files/goal_file_hook — только совместимые оболочки.
Исторические отчёты и журналы не переименовываются.

## Подключение, владелец и вход Windows

setup_shared_continuator.py по разрешению пользователя подключает проект,
сохраняет резервную копию hooks.json и готовит одну общую группу SessionStart /
UserPromptSubmit / Interrupt с видимым именем «CD5 controls: Continue Planner / Stop Planner».
Точное определение требует штатного доверия человека в Hooks. Установка не
создаёт continue_planner и не удаляет действующий запрет.

Текущий Planner автоматически берётся из CHECKPOINT.owner.thread_id при каждом
обходе и перед отправкой. Служба следует принятой передаче владельца, но сама
её не проводит. Старый чат не получает новых продолжений и не управляет controls.
Неопределённая отправка не повторяется. Общая блокировка на учётную запись
не допускает второй экземпляр даже с другим путём конфигурации.

Одна запись HKCU Run «CD5 Continuator» запускает pythonw при входе Windows.
Штатное событие подключённого HQ передаёт действительное подключение Codex;
служба не зависит от окружения текущего хода, не выдумывает pipe/credentials
и не создаёт второй app-server. Без подключения ждёт без модели. При смене
подключения переподключается; реальность связи проверяется host-вызовом квоты.

Команда подготовки установленным Python:

```
setup_shared_continuator.py --home <user-service-home> --root <authorized-project> --hooks-file <user-hooks.json> --app-tools-cache <actual-app-tools-cache> --mac-script <installed-mac-script> --model <checked-model> --authorized --install-logon
```

Запуск: shared_continuator.py --home <user-service-home>. Проверка допускает
конечный --seconds1–600. Перед миграцией завершить только проверенный свой PID;
сохранить controls и счётчики. REGISTRY/CONNECTION, controls, журналы и credentials
не коммитить. При каждом сообщении проверяется точный ID модели MAC.
Закрытая/неизвестная квота запрещает отправку; после неё требуется явный
Continue Planner. Автоматическое квотное восстановление не добавляется.
Реальный вход Windows/перезапуск Codex не объявлять проверенным по одному CONFIG.

## Удаление завершённых тестовых обработчиков

После явного разрешения пользователя cleanup_continuator_hooks.py может удалить
восемь известных регистраций старых connection-probe / Stop trial / event-probe.
Нужно передать точные пути development-root, connection-probe, technical-target,
актуальное hook-definition.json и папку резервных копий. Программа проверяет
ожидаемые количества1/2/5, сохраняет исходные байты hooks.json, оставляет текущие
три общих определения и любые посторонние hooks. Частичное несовпадение запрещает
запись. Исторические скрипты и результаты не удаляются. Смена индексов может
потребовать штатного доверия заново; trusted_hash не копировать и не подделывать.

## История проверок

30Oct2026 прежний однопроектный стенд подтвердил два внешних продолжения,
ручной Interrupt, приоритет Stop при обоих файлах и сохранение запрета после
перезапуска сервиса. Это история узкой проверки, не доказательство новой
многопроектной службы или реального входа в Windows. Результаты новой проверки
записываются отдельно, с явным разделением живых и модельных стендов.
