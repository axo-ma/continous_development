# Continuous Planner: квота не меняет controls

Краткий обязательный контракт зафиксирован в references/continuous-planner-contract.md.
При достижении usedPercent>=90 Planner сохраняет continue_planner и заканчивает
ход. Continuator проверяет свежую квоту без модели, не отправляет продолжения
при90%/выше или неизвестной квоте и автоматически возобновляет отправки при<90,
если прежнее разрешение сохранено, нет Stop и чат свободен. Новая команда не нужна.
Ручной Stop всегда имеет приоритет; ожидаемое завершение и обязательный вопрос
остаются отдельными причинами снять разрешение. Научных прав Continue не даёт.

Удалена старая липкая блокировка quota_hold_permission, зависящая от mtime файла;
сохранённые старые значения безопасно игнорируются. Исправлены автоматическое
сообщение, действующие CD5/MAC инструкции и профиль владельца. Worksheet HQ
исправил свои технические правила отдельно (bd46a0b, push подтверждён), сохранив
WAIT_USER, scientific_calls_authorized=0, отсутствие Continue и paused native Goal.

Проверено266 тестов, в том числе90→100→0 без изменения файла, Stop во время
квотной паузы с перезапуском, старое сохранённое quota-состояние и неопределённая
отправка без повтора. После последней правки retired template его2 теста также
прошли. Регрессии текущих CU/Continuator сохранены; полноценная новая система
учёта Progress Report остаётся отдельной незавершённой задачей.

Также устранена повторявшаяся Windows-ошибка кратковременного запрета атомарной
замены status-файла: ограниченное повторение сохраняет прежнее состояние, а при
постоянном отказе не теряет файл и очищает временный. Это не повторение отправки.

Доверенные hooks не меняются: у них сохранён прежний точный snapshot маршрутизации
команд. Перезапускается только одна служба с новым quota-gate; вход Windows не
перезапускается. Личные controls, подключения и журналы в Git не включаются.
