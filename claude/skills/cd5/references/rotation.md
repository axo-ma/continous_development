# Смена штаба

Штаб меняют, чтобы не работать в слишком длинном контексте: в нём агент путается и дорожает каждый ответ.

## Когда предлагать

- Контекст больше ~300 тыс. токенов (`get_usage`). Не оценивать на глаз по длине переписки.
- Закончена тема или веха.
- Первое подтверждённое нарушение роли (штаб сам сделал то, что должен был отдать) или пользователь «выпал из контекста».
- Пользователь сказал «обнови штаб».

Предлагать одной строкой в спокойный момент: «Хорошая точка для нового штаба: состояние записано в CHECKPOINT». Не прерывать идущую подзадачу; дождаться, когда подзадачи закончат или их состояние известно.

## Как передать

Смена владельца — одна контролируемая операция:

1. **Старый штаб** записывает всё новое в память: принятые результаты, следующий шаг, открытые вопросы. `validate`.
2. **Старый штаб** открывает новый: `start_session` — `initiation: "user_asked"`, `context: "fresh"`, папка проекта, без отдельного worktree. Название — `<проект> HQ · ГГММДД-ЧЧММ` (время фактическое). Задание — стартовое сообщение ниже.
3. Сразу `detach_session` нового штаба — он должен быть чатом верхнего уровня.
4. **Новый штаб** читает `CLAUDE.md` проекта, OUTLINE, CHECKPOINT, нужные записи и **подтверждает**: цель, ограничения, STOP, следующий шаг. В память пока не пишет и работу не начинает.
5. **Новый штаб** проверяет, что владелец в CHECKPOINT не менялся с момента передачи, и меняет только `owner.thread_id` на свой `sessionId` (остальное сохранить) через `write-checkpoint`.
6. Старый штаб — архивировать только после «да» пользователя (`archive_session`). Два действующих штаба не оставлять.

Если шаг не удался — посмотреть фактическое состояние, не создавать второго владельца и не дублировать работу.

## Стартовое сообщение нового штаба

```
Это штаб CD5 проекта <проект> (<путь>). Используй навык cd5.
Ты принимаешь штаб у сессии <id старого штаба>. Сначала только прочитай CLAUDE.md проекта,
OUTLINE.md, CHECKPOINT.json и pending-attention и подтверди мне: цель, STOP, следующий шаг.
В память не пиши и работу не начинай, пока не подтвердишь приём (rotation, шаги 4–5).
В первом ответе одной строкой: «Как работать со штабом — скажите „дай гайдлайн“».
```

Лимит использования — не повод для смены штаба. Не запускать преемника, чтобы обойти лимит.
