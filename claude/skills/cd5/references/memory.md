# Память CD5

Папка памяти — `memory_dir` из `.cd5/config.json` (по умолчанию `coordination/cd5`). Ровно пять файлов, шестой не заводить.

| файл | назначение |
|---|---|
| `OUTLINE.md` | план проекта: цель, вехи, риски, критерии, границы |
| `CHECKPOINT.json` | владелец, STOP, текущая задача, следующий шаг, разрешённая автоматика |
| `EVIDENCE.jsonl` | каталог фактов с постоянными id: источники, артефакты, прогоны |
| `KNOWLEDGE.jsonl` | наблюдения, выводы, неизвестное, гипотезы, решения, принятые результаты задач — со ссылками на EVIDENCE |
| `ATTENTION.jsonl` | открытые вопросы, ждущие решения пользователя |

## Кто пишет

- Единственный писатель OUTLINE, CHECKPOINT, KNOWLEDGE, ATTENTION — роль владельца (`owner_role`, обычно `hq` = штаб).
- Подзадачи и агенты (`executor`, `reviewer`, `helper`) могут только дописывать в EVIDENCE — через `project_memory.py append evidence --role executor`.
- Роль в скрипте — договорённость, а не защита. Не выдавать себя за `hq`, если ты не штаб.

## Факт и вывод — раздельно

- **EVIDENCE** — что наблюдали или какой артефакт существует: «прогон run-07 записал отчёт reports/run-07.json, F1 = 0.82 на validation».
- **KNOWLEDGE** — что из этого следует и в каких пределах: «модель B лучше A на validation; на train не проверяли». Каждый вывод — с `refs` на id в EVIDENCE.
- Событие или артефакт сам по себе не доказывает утверждение и не закрывает веху.
- Отсутствие факта — не отрицательный результат. Различать: **неизвестно**, **не проверяли**, **проверили — отрицательно**.

## Принятые результаты задач

Принятую работу записывать в KNOWLEDGE записью `kind: task_result` со `status: accepted`, постоянными `task_id` и `milestone_id`, полями `goal`, `result`, `meaning` и `refs` на EVIDENCE (пример — в [tools](tools.md)). По ним `project_memory.py progress` показывает прогресс по вехам.

- Принять отчёт как запись ≠ результат положительный ≠ веха закрыта.
- Веху в OUTLINE обновлять, только когда принят результат всей вехи.
- Историю прогресса не восстанавливать из прозы и догадок. Нет структурных записей — так и сказать.

## Решения пользователя

- «Человеческая разметка» и решения — только при явном согласии пользователя. Просмотр, клик, показанная карточка, закрытый вопрос — не согласие.
- Замороженные протоколы и прежние оценки не переписывать. Изменение вопроса, критериев, набора данных или бюджета — через штаб и согласие пользователя.

## Архив

Закрытые вопросы и старые факты уходят в холодный архив с сохранением id (`cu_archive.py`). Обычные запросы читают только «горячую» память. Архив целиком в контекст не загружать.
