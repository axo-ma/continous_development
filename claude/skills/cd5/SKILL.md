# CD5 для Claude

**CD5** — способ вести долгий проект так, чтобы ничего не терялось между чатами.

- **Штаб** — один чат, ответственный за проект: обсуждает с пользователем, принимает решения вместе с ним, проверяет результаты подзадач. Только штаб пишет в память.
- **Подзадачи** — отдельные сессии для опытов, разметки, кода, рутины. Возвращают результат штабу.
- **Память** — пять файлов в проекте. Новый штаб читает их и продолжает с того же места.

CD5 работает и без агентов. Когда отдавать работу агентам или подзадачам, решает навык `mac` ([../mac/SKILL.md](../mac/SKILL.md), если установлен).

## Память — пять файлов

Где лежат — `.cd5/config.json` проекта (`memory_dir`, по умолчанию `coordination/cd5`).

| файл | что в нём | кто правит |
|---|---|---|
| `OUTLINE.md` | план: контекст, задача, результат, ограничения, риски, вехи | пользователь руками или штаб через Edit |
| `CHECKPOINT.json` | где мы сейчас: владелец, STOP, следующий шаг | только скрипт |
| `EVIDENCE.jsonl` | факты: прогоны, артефакты, источники | только скрипт, только дописывание |
| `KNOWLEDGE.jsonl` | выводы и решения со ссылками на факты | только скрипт, только дописывание |
| `ATTENTION.jsonl` | вопросы, которые ждут решения пользователя | только скрипт |

**JSON-файлы руками и через Edit/Write не править** — только через `scripts/project_memory.py`. Скрипт проверяет формат, не даёт дублировать id и не теряет старые записи. Формат совпадает с CD5 для Codex: одну и ту же память могут вести оба.

Подробно: [memory](references/memory.md), план — [outline](references/outline.md), команды — [tools](references/tools.md).

## Где скрипты и Python

- Скрипты — в `scripts/` рядом с этим файлом (обычно `~/.claude/skills/cd5/scripts`). Путь проверить, не угадывать.
- Python 3.10+, только стандартная библиотека, **всегда с `-X utf8`** — иначе на Windows русский текст портится молча. Если `python` нет в PATH — поискать в проекте (venv) или спросить пользователя один раз; найденный путь записать в `.cd5/config.json` ключом `python`.

## Порядок работы штаба

Перед любой содержательной работой — [lifecycle](references/lifecycle.md):
1. Прочитать `CLAUDE.md` проекта, `OUTLINE.md`, `CHECKPOINT.json`.
2. `project_memory.py validate` и `pending-attention`; остальное — только нужные записи через `query`/`select`, не файлы целиком.
3. Если STOP активен — ничего не запускать, показать пользователю, чего ждём.
4. Сделать следующий шаг сам или отдать в подзадачу ([coordination](references/coordination.md)).
5. Принятый результат: факт → EVIDENCE, вывод со ссылкой на факт → KNOWLEDGE, новый следующий шаг → CHECKPOINT. Веху в OUTLINE менять только когда принят результат всей вехи.

## Специфика Claude

- **Владелец** в CHECKPOINT — `owner.thread_id` = id сессии штаба (`get_session self` → `sessionId`). У пользователя id не спрашивать.
- **Подзадача** — `start_session` с самодостаточным заданием (шаблон в навыке `mac`). Результат приходит в штаб сам (`<side-sessions-event>`); штаб проверяет его по файлам, а не по отчёту.
- **Агенты** (`Agent`) — для частей работы внутри одного ответа штаба или подзадачи.
- **Штаб — чат верхнего уровня.** Если штаб создан через `start_session` из другого чата — сразу `detach_session`, иначе уйдёт в архив вместе с родителем.
- **Квоты** в процентах, как у Codex, Claude не видит. Поле `continuity.quota_stop_used_percent` в CHECKPOINT остаётся ради совместимости. Если упёрлись в лимит использования — сохранить CHECKPOINT и закончить ответ коротким статусом.
- **Длинный контекст** — повод для смены штаба ([rotation](references/rotation.md)).

## Команды пользователя

| фраза | что делать |
|---|---|
| «Используй CD5 / подключи CD5 к проекту» | новый проект — `init_project.py`; существующий — подключение по [tools](references/tools.md#подключение-существующего-проекта) |
| «Продолжай работу» | порядок работы штаба, начиная с шага 1 |
| «CD5 on / off / status» | [lifecycle](references/lifecycle.md#cd5-onoffstatus); MAC не трогать, STOP не снимать |
| «Покажи внимание» | `attention.py list` → вопросы по одному, [attention](references/attention.md) |
| «Обнови штаб» | смена штаба, [rotation](references/rotation.md) |
| «Дай гайдлайн» | показать [guide.md](guide.md) целиком |

## Твёрдые правила

- **STOP пользователя** действует, пока пользователь сам его не снимет. Смена штаба, установка навыка, «CD5 on» — не снимают.
- **Новый проект начинается со STOP**: сначала цель, риски, критерии в OUTLINE, потом явное «начинай» пользователя.
- **Факт ≠ вывод.** Вывод в KNOWLEDGE ссылается на факт в EVIDENCE. Нет факта — нет вывода.
- **Неизвестно ≠ ноль ≠ отрицательный результат.** Не проверяли — так и писать.
- **Клик, показ карточки, вопрос «объясни» — не решение пользователя.** Решение — только его явные слова.
- **Проверил сам ≠ проверил проверяющий.** В отчёте писать, что из двух было.

Не входит в эту версию: учёт расхода (CU, WU, план и факт, отчёт о прогрессе). Записи EVIDENCE совместимы с ним, учёт можно добавить позже.
